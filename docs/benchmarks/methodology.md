# 批量编辑性能实验方法

只使用自有或明确获授权的样本。公开仓库不保存私人文稿、原文、文件名、路径、哈希、样本专属几何参数、截图或可反向关联样本的运行记录。

## 方法

1. 逐文本片段 COM：按原生文本范围分别写入字体属性。
2. 按文本框 COM：每个文本框一次设置格式，减少跨进程调用。
3. XML 全包压缩：修改 XML 后重新压缩整个包。
4. XML 避免媒体重压缩：复用未修改的压缩 XML，媒体使用 STORE，修改 XML 重新压缩。

四种方法使用相同编辑清单：测试文字标记、字体、字号、文字颜色和背景。保持原文和图片数据，输出副本。规则不是通用排版算法，应查看布局标记和实际预览。

## 计时和验收

分别记录读入、预检、编辑、保存、Office 启动、读回、退出和完整流程。不要把生成文件时间等同于包含验证的时间。轮换方法顺序，报告重复次数和描述统计，说明系统缓存是否受控。

校验原稿未变、文本及样式符合清单、图片保留、对象几何符合阈值、工作进程及自有 Office 实际退出。XML 部件逐字节等价不代表不同保存引擎之间渲染像素一致；视觉复核使用实际 Office 导出，并在必要时隔离进程复核。

## 运行

```powershell
npm run benchmark:fast -- --source "path/to/sample.pptx" --out "outputs/new-run"
npm run benchmark -- --source "path/to/sample.pptx" --out "outputs/comparison"
```

启动前须关闭已有 PowerPoint；脚本不会替用户关闭现有应用。生成的 JSON、PPTX 和 PNG 含敏感运行信息，只留在忽略版本控制的本地目录。发布代码前检查暂存文件及完整 Git 历史。
